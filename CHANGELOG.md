# Changelog

Dated log of changes to the Scribe Coding scaffolding itself (`templates/`, `tools/docs_check.py`, `SCRIBE_CODING.md`). This repo is the factory, not a stamped project — see `AGENTS.md` — so this file plays the role `docs/requirements/CHANGELOG.md` plays inside a stamped project, but for the scaffolding's own methodology and templates.

## 2026-08-02

- **From a btu_v2 review:** Promoted `docs/discussions/` to a constant pattern (was previously conflated with lifescientific's opt-in fit-gap trees) — btu_v2 independently converged on the same "give informal write-ups a home, don't require cross-linking" pattern under the name `design-discussions/`, generalized here since the write-ups aren't always design-specific. Also added the ADR stub-on-retirement convention (`docs/adr/README.md.tmpl`, `docs/technical/25-documentation-authority.md.tmpl`) and a `docs/user/` opt-in row for operator/end-user-facing doc trees, both sourced from btu_v2.
- **From a cofferdam review, refined during design discussion:** cofferdam's "definition of done" checklist doesn't need a new doc — `05-implementation-index.md.tmpl` already carries a Planned/Partial/Implemented status column, and data-migration-etl's `docs/open-work.md` backlog (status vocabulary: `open`/`blocked`/`in_progress`/`done`/`deferred`) is the same idea in more granular, work-item form. Also added an ADR-deletion hygiene note (delete an ADR that never recorded a real decision, sourced from cofferdam's ADR-0001/0009 practice) without changing the existing archive-and-stub convention — kept deliberately, since hiding superseded ADRs from AI context is the point, not a drawback. Created `open/OPEN_WORK.md.tmpl` (status vocabulary from data-migration-etl; its `done` definition is where cofferdam's DoD checklist actually landed) and, on review, noticed `OPEN_QUESTIONS.md` (formerly `docs/requirements/04-open-questions.md`) and `OPEN_DECISIONS.md` were the same kind of document as the new file — short, high-churn, action-oriented — but scattered across two unrelated locations. Consolidated all three into a new `open/` directory and added a fourth documentation level for them in `01-documentation-conventions.md.tmpl`. This last move wasn't sourced from any reviewed project; it's a structural cleanup discovered by looking across three of them.
- **Requirements-tree audit:** Confirmed `docs/requirements/` stays clean — its `proposed`/`confirmed`/`deferred`/`rejected` status column tracks requirement settledness, not implementation state; no code-status tracking had crept in.
- **Coding standards gap:** Added `docs/technical/00-coding-standards.md.tmpl` (naming conventions, lint/format tooling, design patterns, library choices) — a gap found when auditing `docs/technical/`, since `AGENTS.md`'s "Coding Standards" section only ever covered requirement-ID citation discipline, not actual code style. Numbered `00` (btu_v2's convention for "read this early"), inside the existing `docs/technical/` tree rather than as a new root-level rules file, since a prior discussion had already ruled out adding more root-level rule files alongside `AGENTS.md`/`CURRENT_CONTEXT.md`.
- **Completion tracking:** Rejected automated "is requirement N done" verification (e.g. grepping test files for requirement-ID citations) as unsound — a citation proves engagement, not correctness, and would create false confidence. Completion is a joint human/AI judgment reached through testing, review, or discussion; tooling's job is only to make sure that judgment is recorded durably. Reworked `05-implementation-index.md.tmpl` with `Requirement IDs` and `Completion Judgment` columns (per-ID verdict, method, date) so a fresh session can answer "what's done, what remains?" without re-auditing the codebase. Also fixed a real gap this surfaced: `open/OPEN_WORK.md`'s `done` rows are explicitly swept away during cleanup, so a judgment recorded only there would be lost — the index (never swept) is now the durable home, and `OPEN_WORK.md`'s `done` status and sweep rule both now require the judgment to land in the index first. `AGENTS.md.tmpl` updated to require recording a judgment immediately when reached, even in review-only sessions with no code change.
- **From a job_aggregator review:** Added a "Stakes" section to `docs/requirements/00-overview.md.tmpl` (audience, backward-compatibility expectations, data at risk, rigor this implies) — sourced from `prototype-mindset.mdc`, an always-loaded rule declaring the project a zero-user local prototype and recalibrating everything downstream (refactor freely, skip migration paths, delete over deprecate). Every project reviewed before this one implicitly assumed production/client-facing stakes; nothing in the scaffolding previously asked how much rigor a given project actually needs before applying ADR discipline, fail-closed engineering axioms, or the completion-judgment ledger by default. Stated once in the overview instead of re-decided doc by doc. `dbconform` review turned up no scaffold changes — it validated existing "adopt when needed" decisions (a single running `design-decisions.md` instead of `docs/adr/`, and a requirements index collapsed into the always-loaded rules file) rather than surfacing new gaps.
- **Duplication/consistency audit across all templates:** thinned four full-text rule restatements to owner-doc-plus-pointer (`AGENTS.md.tmpl`'s completion-judgment bullet and requirement-ID-visibility bullet now point to `05-implementation-index.md.tmpl` and `docs/requirements/README.md.tmpl` respectively instead of restating their rules; `docs/requirements/README.md.tmpl`'s archive mention and `01-documentation-conventions.md.tmpl`'s `archived` status definition now point to `docs/archive/README.md.tmpl` instead of restating its rule; `AGENTS.md.tmpl`'s Documentation Hygiene section no longer repeats `01-documentation-conventions.md.tmpl`'s sprawl-control opening sentence verbatim). Fixed a stale numbering comment in `docs/technical/README.md.tmpl` (missed `00` when `00-coding-standards.md` was added). Fixed structural inconsistency across the three `open/` siblings: `OPEN_QUESTIONS.md.tmpl` was missing the `Status Values` table its siblings have — added one; `OPEN_DECISIONS.md.tmpl`'s example ID (`EXAMPLE-001`) didn't follow the `{{ID_PREFIX}}-<LETTER>-NNN` convention its siblings use — fixed to `{{ID_PREFIX}}-D-001`. Extended `docs/requirements/README.md.tmpl`'s identifier registry (previously `FUN`/`NFR`/`AC` only) to include `Q`/`D`/`W`, which were already in use in `open/` but undocumented and unmatched by the recommended search regex — reframed the section as the project-wide `{{ID_PREFIX}}-*` registry rather than a requirements-only one. Broadened `25-documentation-authority.md.tmpl`'s Post-Implementation Doc Hygiene trigger to explicitly cover a completion judgment reached with no code change, matching the newer, more specific rule in `05-implementation-index.md.tmpl`.
